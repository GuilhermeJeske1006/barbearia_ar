# 0006 — Internacionalização es/pt com middleware de resolução em cadeia

**Status:** Aceito

## Contexto

A plataforma opera na Argentina (espanhol como idioma natural do mercado) mas precisa atender também donos/barbeiros/clientes que preferem português. O idioma precisa ser resolvido de forma consistente em três superfícies distintas — painel administrativo autenticado, página pública de agendamento (visitante anônimo ou identificado por telefone), e notificações assíncronas (WhatsApp/e-mail, sem request HTTP) — cada uma com fontes de sinal diferentes disponíveis.

## Decisão

Cadeia de prioridade única, implementada em `App\Http\Middleware\SetLocale`, aplicada a todo o grupo `web`:

1. Troca explícita nesta request (`?locale=` ou já setado em `session('locale')`).
2. `users.idioma` do usuário autenticado.
3. Cookie `locale` de visita anterior.
4. Header `Accept-Language` do navegador.
5. `barbearias.idioma_padrao` do tenant resolvido (quando houver contexto de tenant).
6. Fallback fixo: `es`.

Moeda **não** segue o idioma — é sempre ARS, formatada como tal independente de `es`/`pt` estarem ativos, porque a operação é 100% Argentina; o idioma muda só o texto da interface.

Textos vivem em `lang/es/*.php` e `lang/pt_BR/*.php` como arrays de chaves nomeadas (`__('agendamento.confirmar')`), nunca a string literal em espanhol usada como chave — evita acoplar a key ao idioma "principal" e torna trivial adicionar um terceiro idioma no futuro.

## Consequências

- Notificações assíncronas (fora de um request HTTP) não passam pelo middleware `SetLocale` — quem disparar um job de notificação precisa resolver o idioma manualmente a partir de `clientes.idioma` ou `barbearia.idioma_padrao` e chamar `App::setLocale()` dentro do job antes de renderizar o template. Isso ainda não está implementado (notificações WhatsApp/e-mail são Fase 6 do roadmap) — é um lembrete para quando forem construídas.
- O cookie de idioma dura 1 ano (`60 * 24 * 365` minutos) — trocar o idioma default de um visitante recorrente exige troca manual explícita, não expira sozinho.
- Como `barbearias.idioma_padrao` só existe quando há tenant resolvido, uma request para uma rota sem contexto de tenant (ex.: página de marketing/login do Super Admin) pula direto de "sem cookie, sem Accept-Language reconhecido" para o fallback `es` — aceitável dado que o público dessas rotas é interno/administrativo.
